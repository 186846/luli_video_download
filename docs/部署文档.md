# 速下 SpeedyDL — 部署文档

> 文档用途：本地联调与单机/演示环境部署说明。  
> 关联文档：[需求分析](./需求分析.md) · [方案设计](./方案设计.md) · [接口文档](./API.md)

**仅供个人学习。请勿公网大规模对外提供下载服务。**

---

## 1. 部署形态一览

| 形态 | 适用 | 访问方式 |
|------|------|----------|
| **开发联调** | 日常改代码 | 前端 `5173` + 后端 `8000`，Vite 代理 `/api` |
| **同源反代（推荐演示）** | 本机/内网演示、接近生产 | Nginx（或 Caddy）对外 `:80`，静态前端 + 反代 `/api` |
| **纯后端 + 预览** | 临时验收、无 Nginx | `uvicorn` + `vite preview`（需自行处理 CORS/代理） |

前端请求一律走相对路径 `/api/...`（见 `web/src/api/client.js`）。  
**生产/演示务必让浏览器同源拿到 `/api`**（反代），不要依赖开发期 Vite proxy。

## 2. 环境依赖

| 依赖 | 版本建议 | 说明 |
|------|----------|------|
| Python | 3.11+ | 后端 + yt-dlp |
| Node.js | 18+ | 构建前端 |
| ffmpeg | PATH 可执行 | 分离流合并；未安装时部分清晰度会失败 |
| 磁盘 | 视并发与片长 | 临时文件在 `downloads/tmp/`，默认 TTL 15 分钟 |

### 2.1 检查命令

```bash
python --version
node --version
ffmpeg -version
```

Windows 可将 ffmpeg 解压后把 `bin` 加入系统 PATH，新开终端再验证。

## 3. 开发联调（最快上手）

### 3.1 后端

```bash
cd d:\luli
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

- API：http://127.0.0.1:8000  
- Swagger：http://127.0.0.1:8000/docs  
- 健康检查：http://127.0.0.1:8000/api/health  

### 3.2 前端（另开终端）

```bash
cd d:\luli\web
npm install
npm run dev
```

浏览器打开：**http://127.0.0.1:5173**

`web/vite.config.js` 已将 `/api` 代理到 `http://127.0.0.1:8000`。

### 3.3 联调排障

| 现象 | 最可能原因 | 快速检查 |
|------|------------|----------|
| `ERR_CONNECTION_REFUSED` / 5173 | 前端未启动 | `npm run dev`；`netstat` 看 5173 |
| 解析/下载失败且 Network 打到 5173 仍 502 | 后端未启动或端口不对 | 访问 `/api/health`；确认 8000 |
| `/api/direct` 404 | 旧 uvicorn 进程占端口 | 结束占用 8000 的进程后重启 |
| 封面裂图 | CDN 防盗链 | 确认走 `/api/thumbnail`，非直链 CDN |

手机同网访问：开发机防火墙放行 5173/8000，用电脑局域网 IP + 端口；后端 CORS 已放行常见内网 Origin 正则。

## 4. 演示/准生产：构建 + 反向代理（推荐）

目标：浏览器只访问一个源（如 `http://服务器IP`），静态资源与 `/api` 同源，避免 CORS 与代理不一致。

```text
浏览器
  │
  ▼
Nginx :80
  ├─ /          → web/dist（前端构建产物）
  └─ /api/      → 127.0.0.1:8000（uvicorn）
```

### 4.1 构建前端

```bash
cd d:\luli\web
npm install
npm run build
```

产物目录：`web/dist/`。

### 4.2 启动后端（无 reload）

```bash
cd d:\luli
.\.venv\Scripts\activate
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

说明：

- 任务状态在**进程内存**中，**不要多 worker**（多进程会丢任务 / 进度不一致）。并发下载上限见 `MAX_CONCURRENT_DOWNLOADS`。
- 生产监听建议绑 `127.0.0.1`，仅由 Nginx 对外。
- Linux 可用 systemd 托管（示例见下文）。

### 4.3 Nginx 示例

```nginx
server {
    listen 80;
    server_name _;   # 或你的域名

    root /path/to/luli/web/dist;
    index index.html;

    # Vue SPA：前端路由回退（当前为单页，仍建议保留）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 同源反代
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 下载/字幕可能较大，按需放宽
        client_max_body_size 20m;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}
```

Windows 可用 [Caddy](https://caddyserver.com/) 做同样事，示例：

```caddyfile
:80 {
    root * D:\luli\web\dist
    encode gzip
    handle /api/* {
        reverse_proxy 127.0.0.1:8000
    }
    handle {
        try_files {path} /index.html
        file_server
    }
}
```

### 4.4 验收清单

1. 打开站点首页，品牌与输入框正常  
2. `GET /api/health` 返回 `ok: true`  
3. 粘贴样例 URL → 解析 → 选清晰度 → 下载 → 浏览器收到文件  
4. 封面正常（走 `/api/thumbnail`）  
5. 确认 `downloads/tmp/` 会随 TTL 清理，磁盘不无限涨

## 5. 可选：Linux systemd 托管后端

`/etc/systemd/system/speedydl.service` 示例：

```ini
[Unit]
Description=SpeedyDL FastAPI
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/luli
Environment=PATH=/opt/luli/.venv/bin:/usr/local/bin:/usr/bin
ExecStart=/opt/luli/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now speedydl
sudo systemctl status speedydl
```

前端构建产物更新后，覆盖 `web/dist` 并视情况 `nginx -s reload` 即可，无需重启 API（除非改了后端）。

## 6. 配置与运维要点

配置集中在 `app/config.py`：

| 配置 | 默认 | 部署时注意 |
|------|------|------------|
| `DOWNLOAD_DIR` | `downloads/tmp` | 保证进程可写；定期观察磁盘 |
| `FREE_MAX_HEIGHT` | 720 | 免费清晰度上限 |
| `MAX_CONCURRENT_DOWNLOADS` | 2 | 带宽/磁盘紧张时再调低 |
| `FILE_TTL_SECONDS` | 900 | 临时文件存活；下载后尽快取走 |
| `MAX_FILE_BYTES` | 2 GiB | 软上限说明，防极端大文件预期 |

演示 VIP：`vip_token=demo-vip`（非真实支付）。公网演示务必在文案中标明学习用途。

### CORS

开发态 CORS 已允许 Vite 与常见局域网 Origin。  
**同源反代部署后**，浏览器同源请求 `/api`，一般不再依赖跨域；若仍前后端分端口暴露，需把真实前端 Origin 写进 `app/main.py` 的 `allow_origins`。

### 安全与合规（必读）

- 服务会代用户向第三方拉取媒体，存在带宽、版权与平台封禁风险  
- 封面代理含基础 SSRF 防护，仍不建议对不可信公网无限制开放  
- 无账号体系、无真实支付；任务在内存，进程重启即丢  
- 不适合作为商业多租户下载站

## 7. 目录与发布物

```text
luli/
  app/                 # 后端源码（运行时需要）
  web/dist/            # 前端构建产物（Nginx root）
  downloads/tmp/       # 运行时临时文件（勿提交；需可写）
  requirements.txt
  .venv/               # 服务器上自建虚拟环境
```

建议不要把 `.venv`、`node_modules`、`downloads/` 打进发布包；在目标机执行 `pip install` / `npm ci && npm run build`。

## 8. 常见部署问题

| 问题 | 处理 |
|------|------|
| 合并清晰度报 ffmpeg 相关错误 | 安装 ffmpeg 并保证服务进程 PATH 可见 |
| 下载中进度正常但取文件 404 | TTL 已清理或 task 已消费；缩短操作间隔 / 调大 TTL |
| 多开 uvicorn worker 进度错乱 | 改为 `--workers 1` |
| 仅部署了 `web/dist` 未反代 | 页面能开但解析失败；补上 `/api` → 8000 |
| Windows 杀毒锁临时文件 | 将 `downloads/tmp` 加入排除或换目录 |
